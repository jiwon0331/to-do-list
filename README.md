# Daily Todo

## 프로젝트 소개

HTML·CSS·Vanilla JavaScript로 만든 개인용 Todo 앱입니다. 서버, 데이터베이스, 외부 라이브러리, 빌드 도구 없이 실행합니다.

## 파일 구조

```text
todo-app/
├── index.html
├── style.css
├── script.js
└── README.md
```

- index.html: 날짜별 진행률, 월간 캘린더, Todo 추가, 카테고리 관리, Todo 목록
- style.css: 반응형 배치, 배지, 완료 상태, 편집 UI, 진행률 전환
- script.js: Todo·카테고리 CRUD, 저장·마이그레이션, 화면 갱신
- README.md: 실행·사용·저장·검증 안내

## 실행 및 주요 기능

네 파일을 같은 폴더에 두고 index.html을 브라우저에서 직접 엽니다.

### Todo

- 내용·카테고리·날짜를 선택한 뒤 추가 또는 Enter로 등록합니다. 빈 문자열·공백은 등록하지 않습니다.
- 체크박스로 완료/미완료를 전환합니다. 완료 항목은 취소선과 흐린 글자색으로 표시합니다.
- 텍스트 더블클릭 또는 수정 버튼으로 인라인 편집합니다. Enter·저장으로 반영하고 Escape·취소로 되돌립니다.
- 편집 행 밖으로 포커스가 이동하면 저장합니다. 빈 값은 기존 값으로 돌아갑니다. 카테고리·저장·취소 사이의 이동은 편집을 유지합니다.
- 삭제 버튼은 해당 Todo를 제거합니다.
- 진행률은 선택한 날짜의 Todo를 기준으로 `5/10 완료 (50%)` 형식입니다. 정수 반올림하며 빈 목록은 0/0 완료 (0%)입니다.
- Progress Bar는 width를 변경하고 0.3초 transition을 적용합니다. 움직임 감소 설정에서는 전환을 끕니다. aria-valuenow도 함께 갱신합니다.

### 카테고리 관리

- 새 이름을 입력하고 추가합니다. trim()으로 양끝 공백을 제거하며 빈 이름과 대소문자만 다른 중복 이름을 거부합니다.
- 수정 버튼을 누르면 이름 입력창이 나타납니다. 저장 또는 Enter로 반영하고 취소 또는 Escape로 되돌립니다.
- 이름 수정 시 id는 유지됩니다. 기존 Todo의 categoryId를 바꾸지 않아도 배지와 선택창에 새 이름이 반영됩니다.
- 삭제 버튼은 반드시 확인창을 표시합니다. 해당 카테고리의 Todo 수를 알려주며, 취소하면 삭제하지 않습니다.
- 확인하면 카테고리와 해당 Todo 전체를 제거하고 두 저장소, 목록, 선택창, 진행률을 갱신합니다.
- 모든 카테고리를 삭제하면 기본값이 다시 생성되지 않습니다. Todo 추가는 비활성화되며, 카테고리 관리에서 새 카테고리를 추가하면 다시 사용할 수 있습니다.
- 긴 이름은 줄바꿈하고 여러 배지는 다음 줄로 배치합니다. 사용자 정의 카테고리에도 배지 스타일을 적용합니다.

## 데이터와 저장

localStorage의 `categories`, `todos` 키에 각각 JSON 배열을 저장합니다.

```javascript
// categories
[{ id: "work", name: "업무" }]

// todos
[{
  id: 1,
  text: "자기소개서 작성",
  categoryId: "work",
  completed: false,
  date: "2026-09-22",
  createdAt: "2026-09-22T09:00:00.000Z"
}]
```

categories 키가 없을 때만 업무·개인·공부를 생성합니다. 저장된 []는 사용자가 모두 삭제한 상태입니다. 새 카테고리 id는 시각 기반 문자열이며 충돌 시 숫자 접미사를 붙입니다.

todos 키가 없으면 이전 `daily-todo.todos.v1`에서 읽습니다. category를 categoryId로 바꾸고 새 키에 저장하며 이전 키는 백업으로 남깁니다. 새 todos 값이 []이면 이전 데이터를 다시 복원하지 않습니다. 기존 id·내용·완료 상태·생성 시각을 유지하고 date가 없거나 올바른 YYYY-MM-DD 날짜가 아니면 실행 시점의 로컬 오늘 날짜로 보완하고 저장합니다. 이미 올바른 date가 있으면 변경하지 않습니다.

존재하지 않는 카테고리를 참조하는 Todo는 자동 삭제하지 않고 안내 배지로 표시합니다. 저장 데이터가 손상되면 원본을 보호하고 안내를 표시합니다. 손상된 Todo 또는 카테고리를 읽은 상태에서는 카테고리 연관 삭제를 차단합니다.

카테고리 삭제는 Todo 저장 후 카테고리를 저장합니다. Todo 저장 실패 시 카테고리 저장도 진행하지 않습니다. 두 localStorage 키는 원자적 트랜잭션이 아니므로 두 번째 저장이 실패하면 디스크에는 Todo 삭제만 반영될 수 있습니다. 오류 안내가 보이면 새로고침 전에 확인하세요. 카테고리 삭제는 선택 날짜뿐 아니라 모든 날짜의 해당 Todo를 대상으로 합니다. 현재 페이지의 변경은 유지되지만 저장하지 못한 변경은 재실행 시 복원되지 않습니다.

같은 브라우저·프로필·파일 위치의 일반 모드에서 저장이 허용되어야 재실행 후 복원됩니다. file:// 저장 지원은 브라우저에 따라 다를 수 있습니다. 비공개 모드, 저장 차단, 데이터 삭제, 파일 이동, 다른 프로필 사용은 저장·복원에 영향을 줄 수 있습니다. 여러 탭 동시 편집의 충돌 해결은 지원하지 않습니다.

## 검증 결과 및 직접 테스트

카테고리 관리에 대해 실제 앱 코드를 DOM·localStorage·confirm 대역에서 실행하여 17개 검증을 통과했습니다. 빈 이름·대소문자 중복 거부, 카테고리 추가와 Todo 지정, 이름 변경과 배지 반영, 새 실행 복원, 삭제 확인 문구·취소, 연관 Todo 삭제, 진행률 갱신, 전체 삭제 후 빈 상태 복원, 새 카테고리 재추가를 확인했습니다.

실제 브라우저 UI와 디스크 저장은 검증하지 못했습니다. 브라우저 도구의 로컬 파일 접근 제한이 있습니다. 다음을 직접 확인하세요.

1. 빈 이름과 Study/study 중복이 거부되고, 정상 이름이 선택창에 바로 나타나는지 확인합니다.
2. 사용자 카테고리의 Todo를 만든 뒤 카테고리 이름을 수정하여 기존 배지에 반영되는지 확인합니다.
3. Todo 여러 개가 속한 카테고리를 삭제할 때 정확한 개수가 표시되고 취소 시 유지되는지 확인합니다.
4. 삭제 확인 후 해당 Todo만 사라지고 개수·진행률이 갱신되는지 확인합니다.
5. 모든 카테고리를 삭제하고 새로고침한 뒤 빈 상태가 유지되는지, 재추가로 정상 사용 가능한지 확인합니다.
6. 브라우저 종료 후 다시 열어 카테고리·Todo·완료 상태가 복원되는지 확인합니다.
7. 모바일과 데스크톱에서 긴 이름·여러 카테고리·이름 수정 폼이 잘리지 않는지 확인합니다.

회원가입, 로그인, 서버, 클라우드 동기화, 알림, 반복 일정, 마감일, 우선순위, Drag & Drop, 검색, 다크 모드는 포함하지 않습니다.

## 월간 캘린더와 날짜 처리

- 시작 시 로컬 오늘 날짜가 선택되고 날짜 입력창에도 오늘을 설정합니다.
- 이전·다음으로 표시 월을 이동합니다. 월 이동 자체는 선택 날짜나 Todo 데이터를 변경하지 않습니다.
- 날짜 버튼을 누르면 선택 날짜, 추가 폼 날짜, 목록 제목·내용, 진행률이 함께 갱신됩니다.
- 오늘은 테두리와 aria-current=date, 선택 날짜는 배경색과 aria-pressed로 구분합니다.
- 날짜별 전체 Todo 개수를 •숫자로 표시합니다. 완료 여부와 무관한 개수입니다.
- 선택 날짜는 목록과 진행률의 공통 필터입니다. 다른 날짜의 Todo는 삭제되지 않고 숨겨집니다.
- 날짜 입력을 별도로 바꿔 추가하면 입력 날짜를 우선하여 저장하고, 새 Todo를 확인할 수 있도록 캘린더와 선택 날짜도 이동합니다.
- 날짜를 바꿀 때 진행 중인 Todo 편집은 저장하며 빈 값이면 취소합니다. 새로고침하면 선택 날짜는 오늘로 돌아오지만 각 Todo의 저장 날짜는 유지됩니다.
- 날짜 필터에는 YYYY-MM-DD 문자열만 사용합니다. UTC 변환 없이 연·월·일을 처리합니다. createdAt은 생성 시각 기록이며 날짜 필터에 사용하지 않습니다.
- 날짜 입력은 0001-01-01~9999-12-31을 지원하고 실제 존재하는 날짜인지 확인합니다.

### 실제 브라우저에서 확인할 최종 항목

- 날짜를 번갈아 선택하며 제목·목록·진행률과 막대 전환 효과 확인
- 달력 클릭 후 기본 날짜 추가, date input으로 다른 날짜에 추가
- 더블클릭·Enter·Escape·외부 포커스 이동, 한글 조합 입력
- 여러 날짜에 속한 카테고리 삭제 확인 및 모든 관련 항목 제거
- 새로고침·탭 닫기·브라우저 종료 후 날짜와 완료 상태 복원
- 모바일 320px/375px, 데스크톱 1280px에서 달력 7열·날짜 입력·긴 카테고리 확인

남은 제한: file:// 저장 정책, 여러 탭 동시 변경 충돌, 두 저장 키의 부분 저장 가능성은 이전과 같습니다. 자정을 넘겨 계속 열린 페이지의 오늘 표시는 다음 캘린더 렌더링 때 갱신됩니다.

## 진행률 제목 표시 개선

updateProgress()는 selectedDate의 월·일을 숫자로 읽어 `9월 22일 진행률` 형식으로 표시합니다. 연도와 앞자리 0은 생략합니다. 날짜 선택·앱 시작 시 제목, 완료 개수, 퍼센트, 막대를 함께 갱신합니다. 표시 월만 이동하면 선택 날짜는 유지되므로 제목도 유지됩니다. 새로고침하면 기존 정책대로 오늘 날짜를 선택합니다.

검증: 실제 updateProgress()로 9월 22일(60%), 9월 23일(25%), 이전·다음 달, 1월 2일, 12월 31일의 제목과 퍼센트·막대 너비를 확인했습니다. 브라우저에서 오늘·이전 달·다음 달 날짜를 클릭하고 새로고침하여 제목과 수치를 확인하세요. 저장 데이터와 키는 변경하지 않았습니다.

## 카테고리 관리 Compact UI

카테고리를 Flexbox 칩으로 배치하고 공간이 부족하면 다음 줄로 넘깁니다. 긴 이름은 칩 내부에서 줄바꿈하며 칩은 부모 너비를 넘지 않습니다. 수정은 ✎, 삭제는 🗑 아이콘으로 표시하고 각 버튼에 카테고리명이 포함된 aria-label과 title을 제공합니다. 키보드 포커스 스타일도 유지합니다.

이름 편집 시 같은 위치에서 입력창·저장·취소가 표시되며, 좁은 화면에서는 편집 컨트롤도 줄바꿈됩니다. 카테고리 CRUD, 삭제 확인, 연관 Todo 삭제, 저장 키 및 선택창 갱신 로직은 변경하지 않았습니다.

직접 확인: 여러 카테고리의 한 줄 배치와 자동 줄바꿈, 320px/375px 화면 및 긴 이름의 가로 넘침 여부, 아이콘의 키보드 접근·툴팁, 수정 저장·취소와 삭제 확인·취소·연관 Todo 삭제를 확인하세요. 실제 브라우저의 시각 검증은 수행하지 못했습니다.

## 날짜 + 카테고리 목록 필터

Todo 목록 위에 전체 및 사용자 카테고리 버튼을 표시합니다. 목록은 선택 날짜와 선택 카테고리를 동시에 만족하는 항목만 표시합니다. 전체 선택에서는 선택 날짜의 모든 Todo를 표시합니다. 진행률은 항상 선택 날짜의 전체 Todo를 기준으로 하므로 필터만 바꿔도 숫자와 막대는 달라지지 않습니다.

- 필터 버튼은 categories 배열에서 생성합니다. 추가·이름 수정·삭제 시 즉시 반영합니다.
- 선택 버튼은 active 스타일 및 aria-pressed로 표시합니다. 긴 이름과 많은 버튼은 자동 줄바꿈됩니다.
- 특정 카테고리에 항목이 없으면 카테고리명이 포함된 빈 상태 메시지를 표시합니다.
- 선택 카테고리가 삭제되면 전체로 돌아갑니다. 다른 날짜로 이동할 때에는 카테고리 선택을 유지합니다.
- 시작·새로고침 시 전체를 선택합니다. 필터는 저장하지 않으며 기존 저장 키·데이터 구조는 바꾸지 않습니다.
- selectedCategoryId는 null일 때 전체입니다. 실제 카테고리 id가 all인 경우에도 충돌하지 않습니다.
- getFilteredTodos()는 목록 전용이며 updateProgress()는 getTodosByDate()를 계속 사용합니다.
- 필터 변경 전 진행 중인 편집은 저장하며 빈 값이면 취소합니다. 편집 중 카테고리를 바꿔 현재 필터를 벗어나면 저장 후 목록에서 숨깁니다.
- 추가 폼의 카테고리는 필터와 독립적입니다. 다른 카테고리로 등록하면 저장은 되지만 현재 필터에서는 보이지 않을 수 있습니다.

검증: DOM·저장소 대역에서 15개 검증을 통과했습니다. 기본 전체, 카테고리 전환, 날짜 교집합, 사용자 카테고리 버튼, 이름 변경, 삭제 후 전체 복귀, 빈 메시지, 선택 ARIA, 날짜 전체 진행률 유지, 새 실행 시 전체 기본값을 확인했습니다.

직접 확인할 항목: 날짜별 카테고리 버튼 전환, 선택 중인 카테고리 삭제, 수정 중 다른 카테고리로 이동, 필터를 바꿔도 진행률이 유지되는지, 모바일에서 긴 필터 이름이 넘치지 않는지 확인하세요. 실제 브라우저 UI 검증은 수행하지 못했습니다.

## UI 통합 검수 결과

카테고리 관리를 Todo 목록 아래로 이동하여 보조 영역이 목록을 밀어내지 않도록 했습니다. 관리 영역의 여백과 제목 크기도 줄이고 칩 배치는 유지했습니다. 긴 카테고리명이 포함된 빈 상태 메시지에 줄바꿈을 적용했습니다. 사용하지 않는 category-legend 스타일과 중복 입력 폼 배치 선언을 제거했습니다. renderTodos()에서 이미 구한 목록을 빈 상태 처리에 재사용합니다.

주요 상태는 todos, categories, selectedDate, selectedCategoryId(null=전체), calendarYear, calendarMonth, editingId, editingCategoryId입니다. 필터는 getFilteredTodos()에서 날짜·카테고리를 함께 적용합니다. updateProgress()는 getTodosByDate()를 사용하므로 카테고리 필터는 진행률에 영향을 주지 않습니다.

실제 앱 코드를 DOM·저장소·confirm 대역에서 실행한 22개 통합 회귀 검증을 통과했습니다.

- 9월 22일 업무 A/B, 23일 업무 C 표시 및 날짜 이동 시 업무 필터 유지
- 필터 안에서 완료·취소·더블클릭·Enter·Escape·삭제가 고유 Todo id에만 적용됨
- 수정으로 카테고리를 변경하면 기존 필터에서 숨고 새 필터에서 표시됨
- 3/5=60% → 4/5=80% → 4/6=67% → 4/5=80% 및 필터 변경 시 진행률 유지
- 카테고리 추가·이름 변경 후 선택창·필터 갱신, 아이콘 접근성 속성 확인
- 삭제 취소 및 연관 삭제, 선택 카테고리 삭제 후 전체로 복귀, 진행률 재계산
- 제목의 선택 날짜 표시, 새 실행 시 저장 데이터 복원

저장 키와 스키마는 바꾸지 않았고 새 기능도 추가하지 않았습니다. 브라우저 도구의 로컬 파일 접근 제한으로 실제 화면·키보드·모바일 가로 넘침·디스크 저장은 직접 검증하지 못했습니다. 320px/375px에서 긴 이름, 편집 폼, 칩 줄바꿈과 실제 브라우저 재실행 후 복원을 확인해야 합니다. 기존 제한인 여러 탭 동시 편집 및 저장 실패 시 두 키의 부분 저장 가능성은 남아 있습니다.

## 키워드 기반 자동 카테고리 분류

새 Todo 내용을 입력하면 등록된 카테고리 중 키워드와 가장 잘 맞는 항목을 자동 선택합니다. 추가 폼 아래에 자동 선택 또는 직접 선택 상태를 표시합니다. 사용자가 선택창을 직접 변경하면 해당 입력을 완료할 때까지 직접 선택이 우선합니다. 내용을 모두 지우거나 추가에 성공하면 직접 선택 고정이 해제됩니다.

기본 키워드 예:
- 업무: 회의, 보고서, 기획, 결재, 고객, 견적, 출장, 프로젝트
- 개인: 장보기, 청소, 세탁, 병원, 약속, 가족, 공과금, 예약
- 공부: 강의, 시험, 과제, 복습, 영어, 독서, 자격증
- 취업/구직: 자기소개서, 이력서, 면접, 입사지원, 채용
- 운동/건강: 헬스, 러닝, 수영, 요가, 스트레칭
- 여행: 항공권, 숙소, 호텔, 여권

카테고리 이름 자체도 키워드로 사용합니다. 취업·운동·여행 등의 규칙은 해당 이름의 카테고리가 등록되어 있을 때만 작동하며 카테고리를 자동 생성하지 않습니다. 기본 work/personal/study id의 규칙은 이름을 바꿔도 유지됩니다.

일치한 서로 다른 키워드 수가 가장 높은 카테고리를 선택합니다. 동점 또는 일치 없음은 현재 선택을 유지하고 확인 안내를 표시합니다. 대소문자를 무시하는 부분 문자열 비교이므로 문맥을 이해하는 AI 분류가 아니며 잘못 추천할 수 있습니다. 선택창에서 수정하세요.

기존 Todo를 재분류하지 않으며 필터·날짜·저장 키와 데이터 구조는 바꾸지 않습니다. suggestCategory()는 추천 계산, updateCategorySuggestion()은 직접 선택 우선 처리 및 안내 표시를 담당합니다. 서버·외부 서비스·라이브러리는 사용하지 않습니다.

검증: 13개 분류 로직 검증을 통과했습니다. 직접 브라우저에서 회의/장보기/영어 입력, 사용자 카테고리 추천, 직접 선택 후 추가·새로고침을 확인하세요. 브라우저 UI 검증은 수행하지 못했습니다.

## 키워드 자동 분류와 설정

새 Todo 입력 시 현재 존재하는 카테고리의 키워드 일치 개수를 비교합니다. 가장 높은 점수의 카테고리를 제안하며 동점·미일치에서는 현재 선택을 유지합니다. 직접 고른 카테고리는 해당 Todo를 추가하거나 입력을 비울 때까지 우선합니다. 기존 Todo는 재분류하지 않습니다.

할 일 추가 영역의 '자동 분류 설정 및 키워드'에서 다음을 변경합니다.
- 자동 분류 ON: 제안 카테고리를 선택창에 적용합니다. OFF: 선택을 자동 변경하지 않습니다.
- 분류 제안 표시 ON: 결과 안내를 표시합니다. OFF: 안내만 숨기며 자동 분류 설정에는 영향을 주지 않습니다.
- 키워드 미리보기: 현재 카테고리별 실제 적용 키워드를 펼쳐 확인합니다. 카테고리 추가·이름 변경·삭제에 따라 갱신됩니다.

기본 두 설정은 ON이며 daily-todo.classification.v1 키에 별도로 저장합니다. Todo·Category 키와 데이터 구조는 변경하지 않습니다. 읽기·쓰기 실패 시 안내하고 앱은 계속 동작합니다.

업무·개인·공부 및 취업·운동·여행 이름에 대응하는 키워드 묶음을 제공하며, 그 외 사용자 카테고리는 이름 자체를 키워드로 사용합니다. 기본 카테고리는 id 기준 규칙도 유지합니다. 영문 카테고리 별칭은 대소문자를 구분하지 않고 단어 단위로 비교하며 한글은 부분 일치를 사용합니다.

검증: 실제 분류·설정 함수로 21개 검증을 통과했습니다. 회의/보고서, 장보기, 영어/시험/복습, 자기소개서/이력서, 헬스/스트레칭, 항공권/숙소, 사용자 이름 키워드, STUDY, homework 오탐 방지, 동점, 빈 문자열, 미일치, 두 ON/OFF의 독립성, 수동 선택 우선, 설정 복원·손상 처리, 빈 카테고리를 확인했습니다.

직접 확인: 입력 중 자동 선택, 수동 선택 유지, 두 체크박스의 네 가지 조합, 새로고침 후 설정 복원, 키워드 미리보기의 긴 문장 줄바꿈을 확인하세요. 실제 브라우저 UI 검증은 미완료입니다. 단순 키워드 방식으로 문맥·부정 표현을 이해하지 못하며 모호한 내용은 수동 확인이 필요합니다.

## 탭·브라우저 종료 후 저장 유지 점검

현재 저장은 sessionStorage가 아닌 localStorage입니다. todos, categories, daily-todo.classification.v1 키를 유지하며 이전 daily-todo.todos.v1은 마이그레이션 원본입니다. 정상 저장값이 있으면 앱 시작 시 기본값으로 덮어쓰지 않습니다. 빈 배열도 그대로 유지합니다. Todo 추가·내용 수정·삭제·완료/취소와 카테고리 CRUD는 즉시 저장하며 자동 분류 설정도 변경 이벤트에서 저장합니다.

이번 수정은 카테고리를 로드할 때 id/name 외의 기존 추가 속성도 유지하도록 보완한 것입니다. 기존 자동 분류 및 미리보기 로직은 변경하지 않았습니다. 현재 파일의 키워드는 categoryRules에 정의된 고정 규칙과 카테고리 이름이며, 별도의 사용자 편집형 키워드 저장 UI는 없습니다. D-day 및 기존 Todo 날짜 변경 UI도 아직 없으므로 해당 변경 저장 경로는 이번 단계의 구현·검증 대상이 아닙니다.

검증: 실제 저장 함수와 모의 localStorage로 17개 검증을 통과했습니다. 세 차례 새 실행 시 Todo·날짜·사용자 카테고리·추가 속성·ON/OFF 복원, 시작 시 불필요한 쓰기 없음, 수정·완료/취소 저장, 손상 Todo와 정상 카테고리/설정의 분리, 빈 배열 유지 등을 확인했습니다. 실제 탭 닫기·브라우저 완전 종료 검증은 수행하지 못했습니다.

직접 테스트: 같은 브라우저·프로필에서 동일한 index.html을 열어 Todo 추가와 카테고리·설정 변경 → 새로고침 → 탭 닫고 같은 파일 열기 → 브라우저 종료 후 같은 파일 열기를 순서대로 확인하세요. 재실행 시 선택 날짜가 오늘로 돌아오므로 이전 날짜 Todo는 캘린더에서 해당 날짜를 선택해야 보입니다. 이는 데이터 삭제가 아닙니다.

file:// 저장 정책, 비공개 모드, 종료 시 사이트 데이터 삭제 설정, 저장 용량 부족, 파일 위치·프로필 변경은 앱 코드만으로 영속성을 보장할 수 없는 조건입니다. 저장 실패 안내가 없는지 확인하세요. 브라우저 도구의 로컬 파일 접근 제한으로 실제 사용자 저장소와 종료 설정을 조사하지 못했으므로 데이터 소실 원인을 확정하지 않았습니다.

## Todo 추가·목록 카드 통합

추가 폼과 선택 날짜 Todo 목록을 하나의 todo-section 카드로 통합했습니다. 날짜별 목록은 내부 todo-list-area에서 구분하며 기존 ID를 유지합니다. 기존 자동 분류 details 패널을 '할 일 추가' 제목 옆으로 이동했습니다. 모바일에서는 제목과 설정 진입 UI가 자연스럽게 줄바꿈됩니다.

이번 수정은 index.html·style.css·README.md에 한정합니다. script.js는 파일 해시로 변경되지 않았음을 확인했습니다. 자동 분류 이벤트·키워드·미리보기·저장 키와 날짜별 제목 갱신 로직은 그대로입니다. 정적 검증으로 ID 중복 없음, section 태그 균형, 같은 카드 안의 추가 폼·목록·설정 요소 존재를 확인했습니다.

직접 확인: Todo 추가, 날짜 클릭 후 목록 제목 변경, 제목 옆 설정 열기·닫기, ON/OFF와 키워드 미리보기, 모바일 320px/375px에서 가로 넘침 여부를 확인하세요. 실제 브라우저 조작·시각 검증은 수행하지 못했습니다.

## 선택형 D-day

Todo 추가 폼의 'D-day (선택)'을 비우면 dueDate:null로 저장하며 시작 날짜 하루에만 표시합니다. D-day가 있으면 date ≤ 선택 날짜 ≤ dueDate인 모든 날짜에 같은 Todo를 표시합니다. 진행률과 캘린더 개수도 같은 범위 기준입니다. 카테고리 필터는 목록에만 적용합니다.

목록에 선택 날짜 기준 D-숫자 또는 당일 D-DAY 배지를 표시합니다. 연·월·일을 정수 일수로 계산하여 시간대와 서머타임의 23/25시간 날짜에 영향을 받지 않습니다. 완료 상태는 기간 전체에서 하나이며 날짜별 별도 복사본을 만들지 않습니다.

수정 버튼 또는 더블클릭 편집 안의 D-day 입력으로 마감일을 바꾸거나 비워 해제할 수 있습니다. 저장/Enter는 검증 후 즉시 저장하고, Escape/취소는 원래 값으로 돌아갑니다. 시작일보다 이른 D-day는 허용하지 않습니다. 잘못된 편집값 상태에서 행 밖으로 이동하면 편집을 취소합니다. 기간을 줄이거나 D-day를 해제하여 현재 선택 날짜 범위에서 벗어나면 저장 후 목록에서 숨겨집니다.

기존 저장 키 todos를 유지하며 dueDate가 없으면 null을 추가해 저장합니다. 잘못된 dueDate도 null로 보완하고 Todo 자체는 보존합니다. 기존 date·완료 상태·분류 설정·키워드 로직은 유지합니다.

검증: 21개 범위·날짜 계산·유효성·마이그레이션 검증 통과. 별도로 편집 저장·현재 날짜 범위 이탈 시 숨김·D-day 해제·완료 상태 유지·잘못된 편집 저장 방지를 확인했습니다. 실제 브라우저에서는 선택형 입력, 9/23~9/27 기간의 날짜별 표시, D-4와 D-DAY, 마감일 변경·해제, 새로고침 복원과 모바일 편집 배치를 확인하세요. 실제 브라우저 조작 검증은 미완료입니다.

## D-day 최종 통합 검수

목록·날짜별 진행률·캘린더 개수는 getTodosByDate() → isTodoVisibleOnDate()의 공통 날짜 규칙을 사용합니다. 일반 Todo는 date 당일만, dueDate가 있는 Todo는 시작일부터 마감일까지 양끝을 포함합니다. 카테고리 필터는 getFilteredTodos()에서 목록에만 추가 적용합니다. 완료 상태는 기간 전체에서 공유하고 마감 이후에도 저장 데이터는 삭제하지 않습니다.

수정 사항: commitTodos()의 흐름을 저장 → 목록 → 캘린더 → 진행률로 정렬했습니다. D-day 편집의 포커스 이탈 저장 시 달력 버튼을 교체하면 이어지는 날짜 클릭이 사라질 수 있어 updateCalendarCounts()로 기존 버튼의 개수와 접근성 설명만 갱신하도록 수정했습니다. 자동 분류·키워드 로직과 설정 UI 위치는 변경하지 않았습니다.

34개 모의 통합 검증 통과: 일반 날짜 Todo와 기간 Todo의 합집합, 2/3=67%, 필터 변경 시 진행률 유지, 23~27일 포함/28일 숨김, 날짜별 D-N/D-DAY, 완료 상태 유지, 달력 개수, 수정 blur 후 날짜 클릭 대상 유지, 마감일 단축·해제, Todo·dueDate·사용자 카테고리·자동 분류 설정의 새 실행 복원, 키워드 미리보기 DOM, ✏/🗑 아이콘, 카테고리 이름 변경·연관 삭제, dueDate 없는 데이터의 null 마이그레이션을 확인했습니다.

요청 시나리오 1~7의 실제 탭 닫기·브라우저 종료는 수행하지 못했습니다. 새 JavaScript 실행과 저장소 대역으로 복원 경로만 검증했으며, 실제 브라우저 영속성 검증과 같지 않습니다. 통합 카드·설정 위치는 HTML 구조에서 확인했고 실제 반응형 시각 검증은 미완료입니다. localStorage 정상값을 시작 시 지우는 코드는 발견하지 않았고 실제 데이터 소실 원인도 확정하지 않았습니다. 동일 브라우저·프로필·파일 위치의 일반 모드에서 재실행 후 작성 날짜를 선택해 확인하세요.

남은 제한: file:// 브라우저 저장 정책, 여러 탭 동시 편집, 두 저장 키의 부분 실패 가능성. malformed dueDate는 Todo를 삭제하지 않고 null로 보완합니다. 기간 내 완료 표시는 하나의 Todo 상태를 공유하며 일별 독립 완료 기록은 제공하지 않습니다.
